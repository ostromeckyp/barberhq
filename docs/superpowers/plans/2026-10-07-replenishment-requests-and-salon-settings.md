# Whole-request replenishment and salon settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Submit several products as one atomic replenishment request, expose complete request history, and give each salon its own low-stock setting.

**Architecture:** Keep Angular feature facades, data-access adapters and Material components. A request header owns item rows and one lifecycle; each command commits all product effects, authorization guards and replay records in one SQL transaction. Prove the connector transaction shape first, then coordinate the preproduction schema/client upgrade without deleting existing history.

**Tech Stack:** Existing pinned Angular 22.2.0, Material 22.2.1, Signal Forms, Firebase Auth/Functions/SQL Connect, PostgreSQL, Vitest and Playwright; classic Firebase Hosting.

**Spec:** [2026-10-07-replenishment-requests-and-salon-settings-design.md](../specs/2026-10-07-replenishment-requests-and-salon-settings-design.md)

## Global Constraints

- “No partial requests/fulfillment for the demo. Approval, dispatch and receipt apply to all items together.”
- “Keep the existing five states: PENDING_APPROVAL, RESERVED, DISPATCHED, RECEIVED, REJECTED.”
- “A draft contains 1–6 distinct products, matching the current demo catalog. Quantities remain integers 1–99 per product.”
- “Canonicalize item ordering for payload comparison so reordering identical items does not change the intent.”
- “Persist a nonnegative integer per salon, default 2, applying to all its products.” Low stock means on-hand <= threshold; valid SQL integer range is 0–2147483647.
- “Assigned salon staff may read/change their own salon setting; HQ may manage salons in its business.”
- “Transient session/read errors preserve pending state and block writes.”
- “Preserve existing requests as one-item requests with the same IDs, status, stock effects and rejection history.”
- “Perform migration only with commands quiescent and an explicit target/backup.”
- “The later replenishment agent still prepares draft items and cannot mutate stock.” PDF/RAG remains outside this increment.
- “Cloud verification remains required before release.” Local evidence never counts as deployed Cloud SQL/App Check evidence.
- Follow `web/AGENTS.md`, `.agents/skills/angular-developer/SKILL.md` and existing Material typography/tokens. Keep the Claude HTML handoff unchanged.

## Review Focus

- Reversed item order and retry keys: identical intent replays once, changed quantities cannot reuse a key (Tasks 1 and 3).
- A delayed response after salon/user navigation: neither request results nor settings may appear in the new scope (Tasks 4, 5 and 7).
- A legacy or unrecognized browser journal: preserve evidence, block new submissions and reconcile rather than discard or resubmit (Tasks 2 and 4).
- Crafted detail return context or missing membership: return only to an authorized list, never an arbitrary URL or another salon (Task 5).
- A settings save whose response is lost: reload the authoritative value/version before another save; never announce success based on an optimistic value (Tasks 6 and 7).
