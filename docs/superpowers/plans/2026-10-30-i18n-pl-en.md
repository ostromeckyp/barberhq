# UI language PL/EN Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Users switch the whole web UI between English and Polish from a dropdown; the procedure assistant answers in the chosen language.

**Architecture:** One `Language` service (signal) is the source of truth; Transloco renders text, a locale-aware `appDate` pipe formats dates, `<html lang>` follows it, and the procedure facade sends it as `answerLanguage`. Facades and TS helpers hold translation keys, never English prose; templates translate. Functions accept `'pl'`, instruct the model to write in the requested language and localise two fixed messages.

**Tech Stack:** Angular 22 (standalone, signals, zoneless), Angular Material, `@jsverse/transloco` 8.x, Vitest (`@angular/build:unit-test`), Firebase Functions v2 + Genkit, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-30-i18n-pl-en-design.md`

## Global Constraints

- Languages: exactly `'en' | 'pl'`; English is default fallback; missing Polish key shows English, never a key.
- Storage key `barberhq.language` in `localStorage`, every access in try/catch; browser default (`navigator.language` starts with `pl` → `pl`, else `en`) only when nothing stored.
- Translation files: `web/public/i18n/en.json`, `web/public/i18n/pl.json`, nested keys, top-level namespaces per area: `common`, `shell`, `auth`, `login`, `access`, `procedures`, `replenishment`, `requests`, `delivery`, `salon`, `hq`.
- English locale for dates: `en-GB` (already used in `salon-inventory.facade.ts`); Polish: `pl`. `LOCALE_ID` stays fixed; formatting reads the `Language` signal.
- No visible key, no reload, no lost form state on switch. A model answer already on screen stays; anything the web app builds re-renders.
- Data is never translated (product names, document content, aliases, notes, file names, `originalWording`).
- Polish UI copy: natural, short; terms: zamówienie (request), stan magazynowy (stock), dostawa (delivery), salon, centrala (HQ), procedura, dokument, karta produktu.
- Keep `tests/unit/code-structure.test.ts` rules: one model per file in `models/`, logic files ≤ ~300 lines.
- AGENTS.md: never read/print/grep `*.local.json` or `.env`. Run `npm run graph:update` after source changes.
- No prod deploy; no Vertex calls without owner approval. Do not commit `web/src/app/core/generated*` changes produced by emulators.
- Each task ends green on: `npm run typecheck`, `npm run test:unit`, `npm run test:web`, `npm run format:check` (only files you touched must be formatted).

## Review Focus

1. **Switch with a form half-filled** (order panel draft, delivery receipt draft, product editor) — text changes, typed values and selections survive. Owned by Task 1 (shell switch does not navigate/reload) and checked in Task 7 e2e.
2. **`localStorage` throws or holds garbage** (`'de'`, `''`) — app starts in browser default, no error. Task 1 unit tests.
3. **Error and status messages built by facades after a switch** (snack bars, inline errors, status chips) show the new language — guaranteed by keys-not-prose rule; Task 1's key check rejects English prose in facades only partially, so reviewers check each feature task's facades hold keys.
4. **Polish question, English documents, `pl` answer** — citations still validated; prompt keeps all JSON/citation rules. Task 2 unit test on prompt + existing citation tests.
5. **Interpolated and plural strings in Polish** (counts like "3 products", "1 item") — Polish has 3 plural forms; use Transloco's ICU-free approach: separate keys `one/few/many` selected by a shared `plural(n)` helper. Task 1 provides the helper with tests; feature tasks use it for every count.

**Interfaces:**
- Produces:
  - `Language` (`providedIn: 'root'`): `readonly current: Signal<AppLanguage>`; `set(lang: AppLanguage): void` (persists, sets Transloco active lang, sets `document.documentElement.lang`); `readonly locale: Signal<'en-GB' | 'pl'>`.
  - `provideI18n(): EnvironmentProviders` — Transloco (`availableLangs ['en','pl']`, `defaultLang` = initial language, `fallbackLang 'en'`, `missingHandler.useFallbackTranslation: true`, `reRenderOnLangChange: true`, `prodMode: !isDevMode()`), `registerLocaleData(localePl)` + `localeEnGb`, and `provideAppInitializer` that loads the active language (and `en` fallback) before first render.
  - `AppDatePipe`: `transform(value: string | Date | null | undefined, format: string, timezone?: string): string` — impure (`pure: false`) or signal-driven; uses `formatDate(value, format, language.locale(), timezone)`; `''` for null.
  - `pluralKey('replenishment.items', n, lang)` → `${base}.one|few|many` for `pl` (1 → one; 2–4 except 12–14 → few; else many), `${base}.one|other` for `en`.
  - `LanguageSelect` component, selector `app-language-select`, `mat-select` with options `Polski` / `English` (option labels are not translated — each in its own language).
  - Key convention: facades/helpers return keys (`string` literal keys or `{ key: string; params?: Record<string, unknown> }` as `TranslatedText` in `core/models/translated-text.ts`); templates render via `transloco` pipe or `*transloco="let t"`.
